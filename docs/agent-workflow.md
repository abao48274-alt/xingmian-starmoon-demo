# Agent 开发工作流

星眠项目采用 **"人 + Agent + 真机"** 的协作模式，让一个人也能高效开发完整 App。

## 核心流程

```
想法/需求
   ↓
Agent 拆解任务（ChatGPT / OpenClaw / Cursor）
   ↓
生成代码 / 修复指令
   ↓
真机测试
   ↓
截图/日志反馈
   ↓
Agent 分析问题
   ↓
生成新修复指令
   ↓
迭代验证
```

## Agent 角色分工

| Agent | 职责 |
|-------|------|
| **ChatGPT** | 方案设计、架构讨论、问题排查 |
| **OpenClaw (星眠)** | 代码审计、记忆管理、日常开发辅助 |
| **Cursor** | 代码修改、Bug 修复、快速迭代 |

## 实战案例

### 案例 1：WebSocket 1006 断线排查

**问题：** App 频繁断开连接，错误码 1006

**Agent 排查过程：**
1. 分析可能原因：网络不稳定、心跳缺失、服务端异常
2. 生成诊断方案：增加连接日志、心跳检测、自动重连
3. 提供代码修改：添加 `onclose` 详细日志、重连逻辑
4. 真机验证：修改 → 同步 → 测试 → 确认修复

### 案例 2：Tailscale 真机连接

**问题：** 真机 App 无法连接 Mac mini 后端

**Agent 排查过程：**
1. 检查后端是否监听 `0.0.0.0`（而非 `localhost`）
2. 确认 Tailscale IP 可达
3. 添加健康检查端点 `/health`
4. 前端增加启动诊断：先 HTTP 检测，再 WebSocket 连接
5. 在状态栏显示具体失败原因

### 案例 3：iOS ATS 明文网络配置

**问题：** iOS App 无法访问 HTTP（非 HTTPS）后端

**Agent 解决方案：**
1. 检查 `Info.plist` 的 ATS 配置
2. 添加 `NSAllowsArbitraryLoads: true`（开发期）
3. 保留域名级例外配置
4. 同步到 Xcode 项目

### 案例 4：TTS iOS 音频解锁

**问题：** iOS Safari/WebView 需要用户交互才能播放音频

**Agent 解决方案：**
1. 检测首次用户点击事件
2. 在点击时初始化 AudioContext
3. 后续音频播放无需再次交互
4. 添加音频播放队列，避免重叠

### 案例 5：键盘避让

**问题：** iOS 键盘弹出时遮挡输入框

**Agent 解决方案：**
1. 监听 `visualViewport` 变化
2. 动态调整消息列表高度
3. 自动滚动到最新消息
4. 兼容不同 iOS 版本

### 案例 6：CellCog 唱歌链路

**问题：** 需要实现 AI 唱歌功能

**Agent 设计过程：**
1. 评估音乐生成方案（CellCog API）
2. 设计链路：LLM 判断意图 → 调用 CellCog → 生成 MP3 → WebSocket 推送
3. 前端实现：接收 `song_url` → 创建 Audio 元素 → 播放
4. 真机验证音频播放兼容性

## Agent 协作的优势

1. **快速迭代** — 真机截图 → Agent 分析 → 生成修复 → 再验证，循环只需几分钟
2. **知识整合** — Agent 能同时理解 iOS、WebSocket、TTS、网络等多个领域
3. **代码审计** — 自动检查硬编码 Key、安全漏洞、协议一致性
4. **文档生成** — 自动生成架构图、API 文档、进度报告
5. **24/7 可用** — 随时可以咨询和协作

## 经验总结

- **真机反馈是关键** — 模拟器和真机行为差异很大，必须真机测试
- **截图比文字高效** — 一张截图能说明的问题，不需要写长篇描述
- **迭代验证要快** — 修改后立即同步测试，避免积累太多未知问题
- **Agent 需要上下文** — 提供完整的错误日志和环境信息，Agent 才能精准排查
- **保持简单** — 最小改动原则，不过度设计
